# yesmath: integer math for bare-metal RISC-V (core module `math`)

One library with a stable API (`include/yesmath.h`), built from the methods
that won contests of candidates in the YesOS lab. Each function has
a scalar version (RV64 with Zbb) and, where it pays, an RVV 1.0 version
picked at run time; both give **identical results**. No floating point.

A product selects it with `CORE_MODULES += math`; without it, `ym_` symbols
are forbidden in the image. YesOS Desktop uses it (pixel rows, the audio ring).

```bash
python3 tools/test_math.py                 # host checks + the kernel's `math test`
python3 math/gen_tables.py > math/ym_tables.c
```

## Layout

| File | Contents |
|---|---|
| `include/yesmath.h` | the API, with its own `ym_*` types (no `<stdint.h>`, no YesOS `types.h`) |
| `math/ym_math.c` | the scalar functions |
| `math/ym_rvv.c` | the vector versions (compiled only with `__riscv_vector`; the vector normalize needs Zvbb, which the core's `-march` does not enable, so it uses the scalar one) |
| `math/ym_dispatch.c` | `ym_init` (V bit of `misa`), scalar/vector choice for the batch functions |
| `math/ym_tables.c` | generated by `gen_tables.py`: log2, 2^x, sin, atan (1024 segments each, error centred), sinc 256 × 8 |
| `math/ym_selftest.c`, `math/ym_shell.c` | the self-check behind `math test`, also built on the host by the test |

In the binary (`llvm-size`, `-O2`): tables 36.0 KiB, code 6.7 KiB (scalar
4.7, vector 1.8, dispatch 0.3); with the self-check and the command the
module adds 45 KiB to the core self-test image.

## API and methods

| Function | Method | Accuracy (measured) |
|---|---|---|
| `ym_log2_q32` | HLL: `clz` + table of 1024 segments | within 2^-23 (worst 8.6e-8) |
| `ym_exp2_q16` | table of 1024 segments + shift | Q16-accurate |
| `ym_sqrt_q16`, `ym_rsqrt_q16` | HLL: exp2(±log2 / 2) | Q16-accurate (worst 0.88 / 0.51 steps) |
| `ym_rsqrt_q32` | HLL, result in Q32 | relative 6.4e-8 |
| `ym_exp_q16`, `ym_ln_q16`, `ym_pow_q16` | HLL | Q16-accurate |
| `ym_sin_q16`, `ym_cos_q16` | table of one turn, 1024 segments | worst 0.65 steps |
| `ym_atan2_q16` | octant + hardware division + table | worst 0.50 steps; 0 for (0, 0) |
| `ym_normalize3_q16`, `_batch` | HLL 1/sqrt in Q32 | worst 0.51 steps |
| `ym_dot_q16` | exact 64-bit sum | exact |
| `ym_gain_q15`, `ym_mix_q15` | saturating Q15 | bit-exact to the reference |
| `ym_biquad_*`, `ym_biquad8_*` | transposed direct form II, states 14 bits wider | SNR 90.0 dB* |
| `ym_fir_sym_q15` | symmetric FIR (half the multiplies) | bit-exact to the full sum |
| `ym_resample_sinc8` | 8-tap windowed sinc, 256 phases, nearest phase | SINAD 56.5 dB (44.1 → 48 kHz, 5 kHz tone) |
| `ym_blur3x3_u8` | separable [1 2 1]², 3 rotating row sums | bit-exact to the direct 3×3 sum |
| `ym_memcpy`, `ym_memset` | words when aligned / RVV e8m8 | exact, nothing written past the end |
| `ym_fill32` | 32-bit words (pixels): pairs per 64-bit store / RVV e32m8 | exact, nothing written past the end |

**Q16-accurate**: within one Q16.16 step (2^-16) of the exact value, or
within 2^-20 of it when the value is large; checked on 20 000 inputs per
function (ranges in `yesmath.h`). Correct rounding would be 0.5 steps.

\* Against the same Q14 coefficients in exact arithmetic, on the contest's
signal (two tones and light noise). On white noise at ±20 000 it measures
81.7 dB.

## Cost

Retired instructions on bare-metal RISC-V, measured in the lab (QEMU 11.1
with `-icount`, V and Zvbb, VLEN 128, kernel flags; the same sources). The
kernel's `math test` prints no costs: the QEMU of `make run` has no
`-icount`, and there `minstret` follows the clock. Per call for the single
functions (including the call and the loop around it); per element, sample,
pixel or byte for the batch ones.

| Function | Scalar | RVV |
|---|---:|---:|
| sqrt / 1/sqrt (Q16) / 1/sqrt (Q32) | 49.0 / 52.0 / 49.4 | |
| log2 / 2^x | 28.0 / 27.6 | |
| e^x / ln / x^p | 44.0 / 40.0 / 60.9 | |
| sin / cos | 26.0 / 28.0 | |
| atan2 | 47.1 | |
| normalize3 (batch, per vector) | 62.2 | 22.7 (with Zvbb; scalar in the core) |
| dot (per element) | 7.0 | 2.3 |
| gain / mix (per sample) | 9.0 / 10.0 | 1.0 / 1.3 |
| biquad, 8 channels (per sample) | 21.1 | 3.8 |
| symmetric FIR, 32 taps (per sample) | 176.1 | 23.9 |
| resample sinc8 (per output) | 49.1 | |
| blur 3×3, 64×64 (per pixel) | 22.7 | 3.3 |
| memcpy, misaligned dst+3 / src+5 (per byte) | 6.0 | 0.05 |
| memset (per byte) | 0.52 | 0.05 |

The scalar memcpy above is the worst case: source and destination differ
modulo 8, so it copies byte by byte (0.88 per byte when they agree, in the
contest).

## What the test checks

`tools/test_math.py` (74 checks):

1. **Host build** (`-DYM_HOST`, ctypes): the accuracy table above, against
   exact math; gain, mix, biquad (outputs and states), FIR, blur, memcpy and
   memset (odd offsets and lengths, guard bytes) against integer references
   written in Python, which must match exactly.
2. **The kernel**: `math test` runs every function on inputs from a fixed
   pseudo-random sequence (`ym_selftest.c`) and prints the FNV-1a hash of
   each one's outputs. Each must equal the host build's of the same file, and
   each vector version's the scalar one's; `math` must report V. A vector
   gain rounded down instead of to nearest fails 2 checks.

## Honest limits

- **Instructions, not cycles.** QEMU counts retired instructions and models
  no caches or pipeline; a vector instruction counts as one whatever its
  length. Table lookups and divisions cost more on real chips. Nothing here
  has run on hardware yet.
- **The scalar fallback is tested, the V-less hart is not.** `ym_init` picks
  the scalar versions on a hart without V, and the test runs them, but no
  YesOS image boots on such a hart today (see the core README's limits).
- In the core the vector normalize uses the scalar loop: it needs Zvbb
  (`vclz`), which the core's `-march` does not enable.
- **Vector state:** the boot enables the vector unit (`mstatus.VS`); tasks
  switch through a function call (v0-v31 are caller-saved), and the build
  proves the trap path never uses a vector register.
- Accuracy is checked on the ranges listed in `yesmath.h`, not proven for
  every input.
- Used by YesOS Desktop only; NAS and Security do not link it.
